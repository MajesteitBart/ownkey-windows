# Ownkey for Windows v0.4.0

Dictation cleanup now preserves the speaker's voice and joins sentence fragments
caused by pauses. Smart formatting adds paragraphs and lists where the meaning
calls for them.

## Fixes and additions

- Settings opens on one UI thread and reuses its window. Closing Settings while
  models are loading no longer leaves callbacks pointing at destroyed widgets.
- The overlay exits when its backend process dies. Startup cleans up matching
  overlays orphaned by older versions, and process checks no longer flash a console.
- OpenRouter and custom OpenAI-compatible providers are available in Settings.
  Custom servers support optional API keys, editable endpoints, and model discovery.
- OpenRouter and custom Chat Completions requests set a 1,024-token output limit
  to avoid reserving the model's maximum capacity for short rewrites. Incomplete
  responses are rejected instead of inserting truncated text.
- API errors show the provider's explanation, including account requirements
  and insufficient-credit errors.
- Public Windows builds require verified Authenticode signatures and timestamps.
  Unsigned development installers remain available for local testing.

## Configuration

Existing configuration files are retained. Select OpenRouter in Rewriting and
enter an API key and model ID, or refresh the model list. Account and model
requirements still apply. For custom servers, enter the full request URL.

## Release packaging

A public Windows installer must pass the signing verifier described in
[Windows release signing](../WINDOWS_RELEASE_SIGNING.md). An unsigned development
installer is not a release-qualified asset.
